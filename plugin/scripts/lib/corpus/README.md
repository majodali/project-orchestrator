# The conformance corpus

Part of the shared grammar unit's travelling set (P1-N009 child B,
node P1-N011, spec T3). What replaces the accidental cross-check that
caught the P2-N009 stage-vocabulary gap: a committed set of minimal
project roots — `fixtures/` — each provoking a specific finding rule
of the current form checker, plus `expectations/`, the findings that
checker actually produced on each fixture at the commit when this
child reviewed and committed them, and `manifest.ts`, the fixture →
rule mapping a verifier reads to confirm coverage.

## What travels, and how

`sync_shared_unit.ts` copies this whole directory — `manifest.ts`,
`README.md`, `fixtures/`, `expectations/` — alongside the canonical
grammar unit (`../plan-register.ts`) to a consumer (spec T3). Nothing
under this directory performs I/O or exports a parser; the fixtures
are inert data, read by whichever tool is pointed at them.

`run_corpus.ts` (one directory up, not vendored — it is a local
harness, not travelling data) runs the checker against every fixture
named in `manifest.ts` and compares the result to the matching file
under `expectations/`, exiting non-zero on any divergence. It is the
oracle half of the differential harness node P1-N012 (child C) builds,
and the durable check that outlives the checker's own predecessor
(spec B4).

## Provenance

Every file under `expectations/` was generated by running the
checker that existed at this child's fixture-review commit against
the matching fixture, once, and reviewing the output by hand before
committing it — spec B3/B4's requirement that the evidence be
generated from the outgoing implementation and reviewed *before* any
retirement commit exists. `git log` on this directory shows that
order directly: every fixture and its expectation land in commits
that predate any commit deleting what produced them.

## Why no fixture, this manifest, or an expectation file names a
   script by its filename

Node P1-N013 (the cutover, this node's fourth child) will search the
repository for `form_check.py`, `journal_tail.py`, `sync_agents.py`
and `python3`, and treat any match outside a stated permitted set as
an orphan reference — a mention a future reader would act on that was
left pointing at a file the cutover just deleted. This corpus commits
before any file is deleted, so nothing here needs the cutover's
retirement to make its wording stale; but a plain filename match would
still cost that search rule an exception it does not need. So every
fixture, `manifest.ts` and every `expectations/*.json` file describes
"the form checker" and "the Python/TypeScript journal_tail
implementations" rather than typing the filename, and this file does
the same. `run_corpus.ts` and `sync_shared_unit.ts` do not follow that
convention — they are harness tools that genuinely invoke the Python
by its real path, and that is exactly the kind of mention the cutover
should still find and reason about when it runs (spec C2, decision on
the harness's own retirement is node P1-N013's, per the parent plan's
breakdown).

No match currently exists in this corpus outside `run_corpus.ts` and
`sync_shared_unit.ts` — checked by grepping this directory for the
four strings above at every commit of this child. If a future fixture
genuinely cannot avoid one, name it here rather than let the cutover
discover it.
